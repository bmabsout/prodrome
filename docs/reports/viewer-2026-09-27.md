## What was built

- **`typst-wasm/`**: the Typst crates at exactly 0.15.1 (`typst`,
  `typst-html`, `typst-syntax`, `typst-ide`), in their own cargo workspace
  with their own `Cargo.lock`, excluded from the root workspace. HTML export
  is `Feature::Html` in the library (0.15.1 has no `html` cargo feature).
  Exports: `compile_html(source, files_json)` answering
  `{html, diagnostics}` with each diagnostic's file and UTF-16 span,
  `highlight(source)`, `complete(source, cursor, explicit?)`,
  `hover(source, cursor)` and `add_font(bytes)`. The world has no
  filesystem, no network and no clock (`datetime.today()` is `none`).
  Packages are found only if their files are passed in, keyed
  `@namespace/name:version/path`. 14 native tests, laws included (UTF-16
  and byte offsets round-trip at every character boundary; highlight spans
  are sorted, disjoint and in units). Flake: `.#prodrome-typst-wasm`, and
  `checks.prodrome-typst-wasm-tests`.
- **`typst/`**: the `prodrome-typst` package. `roadmap` (open items that
  exist at the reading instant, ascending in value, unpriced last, then the
  closed), `item` (body, price and state, marks, detail, spec, explanation,
  history with each event linked to its object file), `ring` (72 wedges
  clockwise from twelve, a tick at now), `bar` (one cell per day, past at 70%
  transparency, a tick at now). Problem < 0.5 `#e55900`, Watch < 0.7
  `#a44554`, else Fine `#379775`, none grey. It reads the core's JSON and
  computes no fulfillment. Works paged and in HTML export (marks become
  inline SVG through `html.frame`). `checks.prodrome-typst` compiles the
  examples to PDF and HTML with nixpkgs' typst 0.15.1.
- **`viewer/`**: TypeScript, typechecked by nixpkgs' `tsc` against the
  wasm-bindgen `.d.ts` files and bundled by nixpkgs' `esbuild`; nothing from
  npm. `view.ts` is the one pure function from objects to the data the
  package reads; `main.ts` holds the one read of the clock. Routes `#/` and
  `#/todo/<id>`. Item text is typeset as Typst markup and, if that fails,
  shown verbatim with a note. The typeset HTML is sanitised (no scripts,
  frames or handlers; links only in-site or http(s)) under a CSP with no
  inline script. The item page has the editor demo: a textarea over its own
  highlighting, completion (typed, or Ctrl+Space), a hover line, diagnostics
  with line:column, live preview; it saves nothing. The service worker caches
  the shell in `prodrome-shell-<build>` (the build is a hash of every input)
  and the objects in `prodrome-objects` forever; `index.json` is network
  first. `viewer/assemble.sh APP STORE SITE` makes a site from any store.
- **`.github/workflows/pages.yml`**: see below.
- **`prodrome-wasm`**, one additive change: `entries` also answers
  `created` (per todo, the first `Created`'s instant and the last one's
  text). A todo with no record has its body only there, and reading it in
  TypeScript would have meant a second parser for SPEC §2.
- **Docs**: README section "The viewer", the layout block with the three
  optional directories set apart, CHANGELOG under Unreleased.

**The CLI's `render`** was left as it is. It prints plain text, and making it
use the package would make `cli/` depend on Typst, which the brief rules out.
A reader who wants a PDF compiles the package's layouts with the `typst`
binary, as `typst/README.md` shows.

## The Pages trigger

`pages.yml` runs on `push` to `main`, on `workflow_dispatch`, and on
`workflow_run` of the `verify` workflow for `branches: [roadmap-data]`,
`types: [completed]`. The build job runs a `workflow_run` only when that
run's `conclusion` is `success` and its `event` is `push`, so a pull request
against `roadmap-data` never deploys, and it checks out
`workflow_run.head_sha`, the exact commit verify passed. It also runs
`prodrome verify` itself before assembling.

Why not `push: branches: [roadmap-data]`: for a push, GitHub reads the
workflows in the pushed commit's own tree. `roadmap-data` is an orphan branch
whose tree holds only `verify.yml`, so that trigger in `main`'s `pages.yml`
would never fire. `workflow_run` is read from the default branch, which is
where this file lives, and the triggering workflow may be on any branch;
`verify.yml` on `roadmap-data` is named `verify`, which is what the trigger
names. Verified in principle against GitHub's documented behaviour, not by a
live run: the first push to `roadmap-data` after this merges is the test.

## Open questions

- **CI time.** `nix flake check` in `ci.yml` now builds Typst twice (for
  wasm32 and natively for its tests) with no binary cache: several minutes
  more per push. A cache (Cachix, or `magic-nix-cache`) would take most of
  it back; so would moving the Typst checks to `pages.yml` only.
- **The environment `github-pages`** must allow deployments from `main`
  (the default). A `workflow_run` deployment runs with `GITHUB_REF` set to
  the default branch, so no extra rule should be needed.
- **HTML export is marked experimental** in Typst 0.15.1 and prints that as
  a warning on every compile. The viewer shows only errors and the editor's
  own warnings; the layouts avoid everything the HTML target ignores.
- **Text colour** is not carried by Typst's HTML export for the prices, so
  the package also puts a class on them (`price problem`, …) and the
  stylesheet colours them. In PDF the colour is Typst's.
- **The past of the bar** is read off `series_knots` with straight lines
  between knots; the ring and the future cells call `fulfillment` directly.
  For a `Decay` in the past the straight line is an approximation where the
  knots are not exact.
- **Found, not fixed:** `prodrome add --deadline D --start N` is refused by
  clap ("cannot be used with"), so `--start`, `--end` and `--lead-up-days`
  cannot be given with `--deadline` as their help says. Outside this change.
- **Found, not fixed:** `cargo clippy -p prodrome-wasm --target
  wasm32-unknown-unknown -- -D warnings` fails on `EventStore::lock_file`
  being dead code for that target. The flake's clippy check is native and
  passes. Outside this change.
